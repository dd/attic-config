# Tweak CLI contract

## Discovery and execution

Каждый твик располагается в `tweaks/NAME/tweak.py`. NAME содержит строчные латинские буквы, цифры и одиночные дефисы между группами символов. Имена `list`, `status`, `boot`, `setup`, `update` зарезервированы для общих команд. Реестра модулей в `attic` нет, новая папка со скриптом обнаруживается автоматически.

`attic NAME COMMAND ARGS...` запускает отдельный процесс Python с `tweak.py COMMAND ARGS...`. Аргументы передаются списком, без shell expansion и без добавления параметров конфигурации. stdin/stdout/stderr наследуются, поэтому работают редактор и интерактивные команды. Код завершения одиночного твика возвращается вызывающему; завершение сигналом преобразуется в `128 + номер сигнала`.

Диспетчер не импортирует Python-модуль и не проверяет имена функций. Скрипт сам разбирает свои команды и параметры, например через argparse. Файл остаётся Python-скриптом; поддержка других языков сейчас не добавлена.

На NAS код выполняется от root, поэтому это доверенный локальный код, а не изолированный плагин. Диспетчер проверяет владельца, POSIX-права и отсутствие симлинков перед запуском от root. Дополнительные файлы обязан проверять сам твик. ACL нужно настроить отдельно.


## Standard commands

Договор для новых твиков:

| Command | Contract |
| --- | --- |
| `--help` и отсутствие команды | Вывести справку без изменений системы |
| `install` | Проверить ОС и параметры, выполнить повторяемую установку; exit 0 означает успешную установку |
| `uninstall` | Удалить только собственные рабочие файлы; допускать повторный запуск |
| `config` | Настроить твик, проверяя значения до изменения действующей конфигурации |
| `status` | Показать состояние без изменений системы; работать без root |
| `apply` | Применить обновлённый код и настройки включённого твика; для отключённого завершиться ошибкой |
| `boot` | Восстановить рабочие файлы после перезагрузки или обновления; допускать повторный запуск и укладываться в 60 секунд |

Любые дополнительные команды и их аргументы принадлежат твику. Не нужно добавлять их в `attic`.

Обязательный набор является соглашением для разработчика, а не проверкой Python API. Неподдерживаемая команда должна завершаться ненулевым кодом. `install` не должен возвращать успех для dry-run или предварительного просмотра, потому что диспетчер считает exit 0 завершённой установкой. Исключение составляют `-h`/`--help`, при которых диспетчер только передаёт вызов, не меняя состояние. Эти флаги зарезервированы для справки, не использовать их как обычные значения параметров.


## Shared helpers

`lib/attic_common.py` содержит общие для твиков функции. Подключение из `tweak.py`:

```python
ROOT = Path(__file__).absolute().parents[2]
sys.path.insert(0, str(ROOT / "lib"))
import attic_common as common
```

| Function | Purpose |
| --- | --- |
| `read_config(root, name, validate)` | Собрать настройки из значений по умолчанию и локальных отличий и проверить результат |
| `edit_config(root, name, validate, apply=None)` | Открыть настройки в `$EDITOR`, проверить, сохранить отличия, вызвать `apply`, откатить при его ошибке |
| `read_enabled(root)` | Прочитать список включённых твиков |
| `secure_path(path)` | Проверить владельца root, POSIX-права и отсутствие симлинков |
| `atomic_write(path, data, mode)` | Атомарно заменить файл |
| `truenas_version()` | Вернуть версию из `/etc/version` без префикса продукта |

Поддерживаемая версия ОС объявляется в каждом твике отдельно, потому что совместимость проверяется для каждого твика.


## Configuration

Значения по умолчанию хранятся в `tweaks/NAME/config.json` и обновляются через Git. Локальные отличия хранятся в `local/config/NAME.json`, каталог доступен только root, поэтому там допустимы чувствительные настройки твика. В редакторе показываются действующие значения целиком; сохраняются только отличия, а ключ, удалённый в редакторе, возвращается к значению по умолчанию. `validate` получает итоговый словарь и отвергает неверные значения исключением `ValueError`. Общий `attic` не читает конфиги твиков.


## Activation and boot

Диспетчер хранит список включённых имён в `local/enabled.json`, исключённом из Git. Отсутствующий файл означает пустой список. Повреждённый или недоступный для чтения файл вызывает ошибку. Операции изменения, включая произвольные команды, и общий boot сериализуются через `local/manage.lock`. Справка и status не требуют этого lock. `attic setup` запускает отдельный внутренний скрипт первоначальной настройки, который сам подготавливает права и затем берёт management lock.

`NAME install` сначала запускает скрипт, затем при exit 0 атомарно сохраняет включение. При ошибке установки существующее включение сохраняется. Если запись состояния не удалась после успешной установки, команда сообщает о частичном результате; исправить хранилище и повторить install.

`NAME uninstall` сначала сохраняет отключение, затем запускает скрипт. Даже ошибка очистки или неверных аргументов оставляет твик отключённым для будущего boot; исправить вызов и повторить uninstall. Рабочие файлы могут остаться до успешной очистки или перезагрузки. Справка uninstall состояние не меняет. Если папки твика уже нет, uninstall только исключает его из списка.

Остальные команды не меняют список включения. Повреждённое состояние обрабатывается как ошибка.

Общий `attic boot` запускает `NAME boot` для каждого включённого имени по алфавиту и ограничивает каждый запуск 60 секундами. После ненулевого exit, превышения времени, отсутствующего скрипта или ошибки запуска он продолжает остальные и возвращает общий exit 1. Порядок по алфавиту не заменяет зависимости, поэтому твики должны быть независимыми. Новые папки автоматически не включаются. Post Init timeout должен учитывать суммарное время.

Общий `status` сначала выводит включение, затем запускает status скрипта; при ошибках продолжает остальные и возвращает 1. Статус runtime и включение различаются, потому что включённый твик может не установиться после обновления ОС. Описательное состояние отсутствующего runtime не является ошибкой выполнения status.

Скрипт можно запускать напрямую для справки и диагностики, например `python3 tweaks/avahi-recovery/tweak.py --help`. Прямой вызов install/uninstall обходит запись включения и общий lock, поэтому обычное управление выполнять через `attic`. Твики не должны рекурсивно вызывать `attic` из команды изменения, иначе команда будет ждать уже занятый lock.


## Testing

Тесты твика хранить в `tweaks/NAME/tests/test_*.py`, использовать уникальные имена test-файлов между твиками. Корневая команда `python3 -B -m unittest discover -s tests -v` обнаруживает их через `tests/test_tweaks.py`.

Проверять разбор команд, справку без побочных эффектов, коды завершения, валидацию, повторную установку и удаление, ошибки и сохранение чужих файлов. В тестах заменять вызовы systemd и внешних сервисов; файловые операции выполнять во временных каталогах.
