# Tweak CLI contract

## Discovery and execution

Каждый твик располагается в `tweaks/NAME/tweak.py`. NAME содержит строчные латинские буквы, цифры и одиночные дефисы между группами символов. Имена `list`, `status`, `boot` зарезервированы для общих команд. Реестра модулей в `attic` нет: новая папка со скриптом обнаруживается автоматически.

`attic NAME COMMAND ARGS...` запускает отдельный процесс Python с `tweak.py COMMAND ARGS...`. Аргументы передаются списком, без shell expansion и без добавления параметров конфигурации. stdin/stdout/stderr наследуются, поэтому работают редактор и интерактивные команды. Код завершения одиночного твика возвращается вызывающему; завершение сигналом преобразуется в `128 + номер сигнала`.

Диспетчер не импортирует Python-модуль и не проверяет имена функций. Скрипт сам разбирает свои команды и параметры, например через argparse. Файл остаётся Python-скриптом; поддержка других языков сейчас не добавлена.

На NAS код выполняется от root: это доверенный локальный код, а не изолированный плагин. Диспетчер проверяет владельца, POSIX-права и отсутствие симлинков перед запуском от root. Дополнительные файлы обязан проверять сам твик. ACL нужно настроить отдельно.


## Standard commands

Договор для новых твиков:

| Command | Contract |
| --- | --- |
| `--help` и отсутствие команды | Вывести справку без изменений системы |
| `install` | Проверить ОС и параметры, выполнить повторяемую установку; exit 0 означает успешную установку |
| `uninstall` | Удалить только собственные рабочие файлы; допускать повторный запуск |
| `config` | Настроить твик, проверяя значения до изменения действующей конфигурации |
| `status` | Показать состояние без изменений системы |
| `boot` | Восстановить рабочие файлы после перезагрузки; допускать повторный запуск |

Любые дополнительные команды и их аргументы принадлежат твику. Например, `apply` и внутренний `recover` определены только в Avahi, а диспетчер про них ничего не знает. Не нужно добавлять их в `attic`.

Обязательный набор является соглашением для разработчика, а не проверкой Python API. Неподдерживаемая команда должна завершаться ненулевым кодом. `install` не должен возвращать успех для dry-run или предварительного просмотра: диспетчер интерпретирует exit 0 как завершённую установку. Исключение - `-h`/`--help`: при наличии этих аргументов диспетчер только передаёт вызов, не меняя состояние. Эти флаги зарезервированы для справки, не использовать их как обычные значения параметров.

Конфигурация хранится рядом со скриптом. У Avahi это `config.json`, который редактируется через `$EDITOR`; конкретные поля и путь знает только скрипт. Он сам определяет, применять ли изменения сразу. Общий `attic` не читает конфиги твиков.


## Activation and boot

Диспетчер хранит список включённых имён в `local/enabled.json`, исключённом из Git. Отсутствующий файл означает пустой список. Повреждённый файл вызывает ошибку. Операции изменения, включая произвольные команды, и общий boot сериализуются через `local/manage.lock`. Справка и status не требуют этого lock.

`NAME install` сначала запускает скрипт, затем при exit 0 атомарно сохраняет включение. При ошибке установки существующее включение сохраняется. Если запись состояния не удалась после успешной установки, команда сообщает о частичном результате; исправить хранилище и повторить install.

`NAME uninstall` сначала сохраняет отключение, затем запускает скрипт. Даже ошибка очистки или неверных аргументов оставляет твик отключённым для будущего boot; исправить вызов и повторить uninstall. Рабочие файлы могут остаться до успешной очистки или перезагрузки. Справка uninstall состояние не меняет.

Остальные команды не меняют список включения. Скрипт может читать `local/enabled.json` относительно своей копии репозитория, если ему нужен этот контекст. Avahi проверяет включение для apply/boot и применяет изменения config сразу только для включённого твика. Повреждённое состояние обрабатывается как ошибка.

Общий `attic boot` запускает `NAME boot` для каждого включённого имени по алфавиту. После ненулевого exit, отсутствующего скрипта или ошибки запуска он продолжает остальные и возвращает общий exit 1. Порядок по алфавиту не заменяет зависимости: твики должны быть независимыми. Новые папки автоматически не включаются. Post Init timeout должен учитывать суммарное время; отдельного тайм-аута дочернего процесса в диспетчере нет.

Общий `status` сначала выводит включение, затем запускает status скрипта; при ошибках продолжает остальные и возвращает 1. Статус runtime и включение различаются: включённый твик может не установиться после обновления ОС. Для Avahi описательное состояние отсутствующего runtime не является ошибкой выполнения status.

Скрипт можно запускать напрямую для справки и диагностики, например `python3 tweaks/avahi-recovery/tweak.py --help`. Прямой вызов install/uninstall обходит запись включения и общий lock, поэтому обычное управление выполнять через `attic`. Твики не должны рекурсивно вызывать `attic` из команды изменения: это приведёт к ожиданию уже занятого lock. Внутренний systemd-вызов Avahi `recover` работает напрямую и использует свои runtime locks.


## Testing

Тесты твика хранить в `tweaks/NAME/tests/test_*.py`, использовать уникальные имена test-файлов между твиками. Корневая команда `python3 -B -m unittest discover -s tests -v` обнаруживает их через `tests/test_tweaks.py`.

Проверять разбор команд, справку без побочных эффектов, коды завершения, валидацию, повторную установку и удаление, ошибки и сохранение чужих файлов. В тестах заменять вызовы systemd и внешних сервисов; файловые операции выполнять во временных каталогах.
