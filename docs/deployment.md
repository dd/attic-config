# Deployment

## Prerequisites

Цель - Linux-based TrueNAS 25.10.7 с systemd и Python 3 (`/usr/bin/python3`). CORE не поддерживается.


## Persistent source

1. Создать на пуле отдельный dataset, например `/mnt/POOL/system`, без SMB-шары и с владельцем root. Домашний каталог не подходит, потому что он принадлежит пользователю. Dataset должен быть доступен к моменту Post Init. Для зашифрованного dataset требуется разблокировка до запуска задания; иначе твики не восстановятся, и нужно выполнить `sudo ./attic boot` вручную после разблокировки.
2. Родительские каталоги этого dataset должны принадлежать root и быть недоступны для записи группе/остальным. Setup проверит их, но не изменит. Настроить также ACL dataset, потому что код проверяет POSIX mode bits, но не анализирует ACL. Не размещать проект в SMB share или dataset, куда могут писать приложения или обычные пользователи.
3. Клонировать репозиторий и запустить setup:

```sh
cd /mnt/POOL/system
sudo git clone https://github.com/dd/attic-config.git
cd attic-config
sudo /usr/bin/python3 attic setup install
sudo /usr/bin/python3 attic setup status
```

Репозиторий приватный, поэтому для clone и pull на NAS нужен доступ только на чтение, например deploy key. Токен не указывать в URL, иначе он сохранится в `.git/config`. Не выполнять автоматический `git pull` от root при загрузке.

Setup закрепляет владельца root:root и убирает group/world write и setuid/setgid внутри папки проекта, включая `.git`. Содержимое файлов не меняется. Предварительно проверяет дерево и отказывается от символических ссылок, hard links и специальных файлов. За пределами проекта права не изменяются. Если родительский dataset не подходит, setup завершится с указанием проблемного пути; исправить настройки dataset через TrueNAS, не менять рекурсивно права всего пула.

Установка выполняется на месте. Нет копирования в системные каталоги, установки пакетов, `venv` или изменения PATH. Все дальнейшие команды можно вызывать через `/usr/bin/python3` по абсолютному пути или из этой папки.

После проверки setup вызывает локальный `/usr/bin/midclt` от root и регистрирует Post Init. Ни один твик не устанавливается и не включается. При ошибке middleware закреплённые права сохраняются; после устранения ошибки повторить setup install. После timeout API не создавать дополнительное задание вручную, потому что следующий запуск сначала перечитывает состояние.


## Reboot persistence

`attic setup install` создаёт задание, которое можно увидеть в **System > Advanced Settings > Init/Shutdown Scripts**:

| Field | Value |
| --- | --- |
| Description | attic-config: managed boot v1 |
| Type | Command |
| Command | `/usr/bin/python3 /mnt/POOL/system/attic-config/attic boot` |
| When | Post Init |
| Enabled | Yes |
| Timeout | 120 seconds для новой установки |

При повторной установке setup использует то же задание и сохраняет его timeout. Изменить его можно командой `sudo ./attic setup install --timeout 240`. Путь с пробелами/спецсимволами автоматически заключается в shell quotes.

`attic boot` ограничивает каждый твик 60 секундами, поэтому зависший твик не мешает следующим. Общий timeout задания должен вмещать худший случай, то есть 60 секунд на каждый включённый твик.

Ранее созданное вручную единственное задание с точно той же командой и POSTINIT setup принимает под своё управление. При дубликатах или неожиданно изменённой команде помеченного задания setup отказывается от изменений. Посторонние задания не удаляются.

Предполагается одна управляемая установка attic на NAS. Не запускать setup одновременно из нескольких копий. Задание хранится в конфигурации TrueNAS; `local/` нужно резервировать отдельно. Экспорт конфигурации TrueNAS не содержит файлы dataset.

Post Init вызывает `attic boot`, который применяет только твики из `local/enabled.json`. Рабочие файлы твиков могут лежать в `/run`, который очищается при загрузке; до выполнения задания такие твики не действуют. Не полагаться на точный порядок запуска всех служб относительно Post Init.

После обновления ОС не считать старые твики автоматически совместимыми. Проверка версии остановит их установку, а `attic status` покажет твик включённым, но не установленным. Проверить новую версию и поведение твика перед изменением version guard.


## Update

```sh
cd /mnt/POOL/system/attic-config
sudo git pull --ff-only
sudo /usr/bin/python3 attic setup install
sudo ./attic boot
./attic status
```

`local/` исключён из Git, поэтому pull не затрагивает настройки и список включения. Setup повторно проверяет права дерева. `boot` повторно применяет все включённые твики и продолжает работу после ошибки одного из них. Никогда не перезаписывать `local/` состоянием с другого сервера.

Если твик удалён из репозитория, но остался включённым, `boot` будет завершаться ошибкой. Исключить его из списка можно командой `sudo ./attic NAME uninstall`. Кода твика больше нет, поэтому очистки не будет; рабочие файлы в `/run` исчезнут после перезагрузки.


## Uninstall

Команда `sudo ./attic NAME uninstall` удаляет один твик и оставляет общее задание Post Init. Для полного удаления общей интеграции:

```sh
sudo /usr/bin/python3 /mnt/POOL/system/attic-config/attic setup uninstall
```

Setup отключит своё Post Init, последовательно удалит включённые твики и удалит задание после успешной очистки. Если удаление твика не удалось, задание остаётся отключённым, а неочищенные твики остаются в списке для повторной попытки. Исходники и `local/` не удаляются. Ранее отключённые твики с остаточными файлами при необходимости очищать отдельно через их uninstall.


## Relocation

Папка репозитория одновременно является местом установки. Для переноса переместить её целиком вместе с `local/` в другой защищённый dataset, затем выполнить `sudo /usr/bin/python3 /новый/путь/attic setup install`. Setup обновит абсолютный путь в существующем помеченном задании. До этого автозапуск указывает на старое место.

Не продолжать управление из оставшейся старой копии. Uninstall из неё откажется удалять интеграцию, если задание уже указывает на новую папку. Setup install намеренно перепривязывает единственную установку к папке, из которой запущен.


## API references

Регистрация использует штатные методы TrueNAS 25.10 [create](https://api.truenas.com/v25.10.0/api_methods_initshutdownscript.create.html), [update](https://api.truenas.com/v25.10.0/api_methods_initshutdownscript.update.html) и [delete](https://api.truenas.com/v25.10.0/api_methods_initshutdownscript.delete.html). Схемы сверены 2026-10-30; вызовы реального middleware на NAS ещё не проверены.
